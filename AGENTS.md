# Правила проекта CopyBoard

## Changelog

- Каждое изменение, заметное пользователю, добавляй в `CHANGELOG.md` в раздел `Unreleased`.
- Используй подразделы `Added`, `Changed`, `Fixed`, `Deprecated`, `Removed` и `Security` по формату Keep a Changelog. Создавай только нужные подразделы.
- Описывай результат для пользователя, а не внутренние шаги реализации. Одно логическое изменение — один короткий пункт.
- Чистый рефакторинг, форматирование и технические действия без изменения поведения в changelog не добавляй.
- Не редактируй вручную заголовок выпущенной версии и не переписывай существующие теги Git.

## Выпуск версии

- Перед выпуском проверь, что рабочее дерево чистое, `Unreleased` содержит все изменения, а `npm run lint` и `npm run build` проходят.
- Для патч-релиза используй действие среды `Release Patch` или команды `npm version patch` и `git push origin main --follow-tags`.
- `npm version patch` автоматически переносит содержимое `Unreleased` в раздел новой версии, добавляет дату, создаёт commit и тег.
- После отправки тега дождись успешной сборки Windows и macOS в GitHub Actions и проверь файлы и описание версии на странице GitHub Release.
- Обычный push ветки не выпускает установщики. Публичный Release создаётся только по тегу версии.
